# AGENTS.md - EyrAgents

EyrAgents is a standalone GNU Stow repository for shared Claude Code and OpenCode configuration. It has no host-dotfiles repository dependency. Keep changes portable across the supported Omarchy and Arch WSL environments unless a platform-specific scope is explicit.

## Operating Principle

The harness exists to let Claude Code and OpenCode work at full capability without exposing H. A restriction earns its place only by preventing a named exposure: secrets and H's personal folders (denied), and remote, third-party, destructive or hard-to-reverse effects (native ask prompt). Within the authorized scope, everything else runs without prompts, rituals or custom machinery, with the same outcome in both tools. Reads do not prompt, except where a command's read and write forms cannot be told apart by its text; [the access policy](docs/access.md#model) lists those families and their prompt-free alternatives. Before adding a rule, hook, prompt or procedural step, name the exposure it prevents; remove any that prevents none.

## Loading and Ownership

- Claude Code loads `~/.claude/CLAUDE.md`, its user instruction file and a tracked symlink to global guidance, then reads this file natively as the project's `AGENTS.md` (2.1.277 or later; the repository has no `CLAUDE.md`, which would take precedence). OpenCode loads global guidance through its native global `~/.config/opencode/AGENTS.md` symlink and this file; no explicit `instructions` duplicate is configured. The guidance file is not named `AGENTS.md` because both tools auto-load `AGENTS.md` files from subdirectories they read, which would load it twice while working on this repository.
- `agents/.agents/global-agents.md` is the canonical cross-tool policy and `agents/.agents/skills/*/SKILL.md` are the canonical skills, in the tool-neutral package that deploys `~/.agents`, the Agent Skills standard's home. Both tools reach the guidance through tracked global-instruction symlinks. `make stow` links each skill directory whole as `~/.agents/skills/<name>` and `~/.claude/skills/<name>`, since Claude Code reads only `.claude/skills`; OpenCode discovers `~/.agents/skills` natively, and `skills.paths` names it again so the restricted untrusted-checkout launch keeps the skills. Skill executables live in `skills/<name>/scripts/`, the Agent Skills location: the two review bridges under `spar`. Order tools as Claude Code, OpenCode.
- This file owns repository invariants. `README.md` is the public overview and navigation entry point; `docs/setup.md` owns installation/deployment and `docs/operations.md` owns usage/verification. `docs/design.md` owns architecture and rationale. `docs/access.md` owns the cross-tool access comparison, restricted launches, implementation references, and official-source baseline; read it first for access questions and reconcile it through `/eyrsync`. Skills own workflow procedure and script headers own local constraints. `docs/maintenance.md` holds unresolved decisions, deferred work, active limitations, and dated revalidation evidence. Update each fact at its owner and link to it; keep README detail proportional. Git history owns provenance.
- `docs/workspace-guide.html` and `docs/workspace-guide-src/` own the full offline development-workspace reference, including both host profiles and all AI clients. Host configuration work and each host's `/omasync` reconcile `host-reference.json`; `/eyrsync` reconciles `client-reference.json` and client workflows. Follow the guide's maintenance contract and obtain companion edit scope when needed. EyrArcHy/EyrWSL remain implementation twins; EyrAgents builds the guide from its own sources. Preserve component source/runtime evidence and dates. `make workspace-guide` rebuilds the single output and `make check` rejects staleness; neither proves live key delivery.
- Work that spans several steps or sessions keeps one live plan file in `~/Projects/eyrie/scrape/plans/`, as global guidance's Continuity rule says; tracked `docs/handoff.md` carries only concrete cross-host work, never approval.
- Documentation is source-only; Stow deploys package contents. Because the packages are live configuration on a stowed host, an edit to a settings file, skill, or bridge here is active before any commit: for the next session of each tool, and at once in running Claude Code sessions, whose `env` values persist until restart. Run mutation checks on a scratch copy, never on the packages in place; work on this repository only in a session H is watching.

## Security Boundaries

- Authentication, credentials, session state, and generated host state stay out of Git. The tracked Claude settings are the only app-managed rewrite exception; preserve and review those rewrites instead of reverting them.
- Maintain the common finite [protected-path inventory](docs/access.md#protected-paths) across both tools' configurations, with native gaps explicit. It covers credential/auth/key/browser/password-manager stores, environment files, known histories, process environments, raw dumps and recognizable copies, including `*.keytab` and private `ssh_host_*_key`. Keep ordinary configuration, public host keys, `example.env` and `credentials-policy.md` usable. A finite inventory cannot classify arbitrary renamed secrets; search, shell and client-internal coverage differ.
- General-browse exclusions are not blanket OS masks: preserve authorized programs' normal runtime interfaces and task-scoped non-secret diagnostics, while excluding raw payload/interface file-tool targets. Native rules and guidance remain distinct; the access policy owns supported scope and evidence.
- Git internals are protected in layers: native rules deny `.git/**` writes on checked targets, except OpenCode's unchecked [Move-to destinations](docs/access.md#move-destinations). Claude Code's classifier requires explicit instruction for Git configuration changes, with the bounded, pinned-identity Eyrsync reference-updater exception below; OpenCode's named configuration asks remain. Reference authority does not bypass native restrictions or authorize arbitrary config, hook, alias or publication changes.
- Commits and pushes run through the `ship` skill: every card of a round goes into one chat message first, then H approves each `git commit` or `git push` at the tool's native prompt, one prompt per command. Commit-producing and publishing Git forms ask in both tools, also behind `git -C`, `-c` and long global options; publication additionally waits for H's go before the push command runs.
- A failed CI run gets one retry after its cause is diagnosed, approved at the native `gh run rerun` prompt; the ship skill owns the procedure. Restart OpenCode after permission changes before claiming live activation.
- GitHub publication uses HTTPS with the host's standard `gh` credential helper. H handles login, storage and recovery locally; EyrAgents neither inspects credential stores nor configures global authentication. Never launch a nested client, broker or override to bypass a native boundary.
- Trusted-repository defaults are not an isolation boundary against hostile project configuration. Use the restricted launches in `docs/access.md#untrusted-checkouts` for untrusted checkouts.
- Claude Code and OpenCode keep primary web fetch and search. These are egress and authority surfaces for a prompt-injected session, kept by H's choice. Reviewers have the same web and shell access under the same rules.

## Tool Configuration

The [access policy](docs/access.md) compares the tools without equating guidance, native permission, classifier review and live evidence. A policy or tool-surface change keeps its outcomes, implementation references and rationale current; unresolved parity gaps belong in the ledger. Do not broaden a stricter boundary merely to match the other tool.

Every managed tool has a declared reference/evidence strategy, owned by [eyrsync's Sources and Reference Lifecycle](.agents/skills/eyrsync/SKILL.md#sources). `references.txt` declares Claude Code's public release/plugin/support repository and OpenCode's client source repository. Do not claim proprietary Claude CLI implementation evidence from its support clone, or infer installed/hosted behavior from any public client checkout. Inventory missing/stale references and reconcile docs, releases, available source and runtime evidence within the agreed scope; initial creation and preservation-sensitive effects retain their explicit approval boundaries.

GitHub reference entries pin reviewed object IDs. The standalone updater verifies canonical metadata for declared/actual origin endpoints, refreshes with preservation checks, then can reconcile a same-project fetch URL and its own manifest URL. It preserves explicit push URLs and other configuration; identities never auto-change. Missing/different/ambiguous sources, dirty/detached/shared layouts and unsafe/drifting inputs refuse. Partial fetch, checkout or URL progress is reported without rollback. Trusted quiescent inputs and native permissions remain prerequisites; fixture tests are not hostile-writer containment. Eyrsync owns this bounded standing authorization and post-migration documentation reconciliation.

OpenCode 1.18.32 Apply Patch omits Move-to destinations from its Edit request, so only `external_directory` rules check them. Its shell can already write any path the OS permits, so this adds no reach, but no destination-specific Edit rule binds a move. [Move destinations](docs/access.md#move-destinations) holds the versioned source; no gap authorizes bypassing a restriction.

- Claude Code runs in auto mode with bypass disabled and no tracked sandbox. Reads are allowed everywhere except secrets and H's personal folders; persistent scratch has an explicit Edit allow. Deny/Ask precede Allow. The classifier's former named-secret exception is closed by a hard-deny rule, with authorized programs' implicit credential/runtime use kept distinct. Privilege escalation, `gh auth`, credential writes and other agent clients are denied; commits, pushes, remote-changing `gh` commands, `gh api`, destructive or configuration-changing Git commands and SSH ask. The reference-updater exception remains. `/doctor` may rewrite `~/.claude.json` and local allowlists; curate durable rules instead of restoring machine state.
- Claude Code and OpenCode carry an `auditor` agent with the auditor charter `agents/.agents/agents/auditor.md`. It has read, search, shell and web tools but no edit tools; the charter keeps it read-only, and its commands pass the primary's rules. Claude Code's agent body equals the charter. OpenCode's auditor uses `mode: all` so `spar-opencode` can run it headless; a subagent would silently fall back to the build agent. `tests/config-contracts.py` checks both under modeled permission semantics, not live dispatch.
- OpenCode reads everywhere except secrets and H's personal folders (`external_directory` and `read` denies), edits the worktree, persistent scratch and `/tmp/opencode` freely, and asks before other edits (`../* = ask`). Read/Edit subjects are worktree-relative, so the scratch grants use location-independent patterns; external subjects are directory/parent `/*`; a non-Git worktree is `/`, which defeats `../*`. Shell file-command checks and grep lack per-file Read/Edit enforcement. Its command rules match Claude Code's outcomes. No plugins load.
- Each tool's config owns its model choices; nothing else restates them. Claude Code's settings own the primary `model`, which `/model` may rewrite; the auditor's frontmatter and `spar-claude` use the moving `fable` alias. OpenCode's config owns its primary and small models; it needs concrete IDs, so bump them when its catalog lists a newer generation, and its auditor follows the primary model. `tests/config-contracts.py` checks only the `xhigh` effort. Report effective runtime model/effort/tier only from safe client evidence; configured preferences do not fill unknown provenance fields.

## Reviewer Bridges

- Each tool reviews with the other's model through a bridge in the spar skill's `scripts/`: `spar-opencode` from Claude Code, `spar-claude` from OpenCode. A bridge runs one reviewer from the repository root under H's normal settings for that tool (Claude Code with the auditor's tool list and no MCP tools; OpenCode's `auditor` agent), with the shared charter, a hard timeout and session resume. Bridges are the sanctioned route; direct nested client launches stay denied.
- Review-recommended paths: a change to `claude-code/.claude/settings.json`, `opencode/.config/opencode/opencode.json`, a bridge, the auditor charter, or `agents/.agents/global-agents.md` is where a spar or auditor review before the commit card earns its cost. No review is mandatory; findings and their dispositions go in the plan file.

## State and Deployment

- Stow runs with `--no-folding`, so managed parents stay real directories and only leaves are links; each skill directory under `~/.agents/skills` and `~/.claude/skills` is the exception, linked whole so files added to a skill deploy without a restow. Every host-writing Make entrypoint requires the deployed-clone guard. `check-skills` preflights all selected skills before cleanup or conversion; foreign entries refuse unchanged. Cleanup removes only recognized dangling package links and retired directories left empty. `.NOTPARALLEL` serializes one Make invocation, not independent deployment processes or disk failures.
- Run authorized host gates through their reviewed entrypoints when native permissions allow. Never open or dump possibly secret-bearing host state; access refusals, unsafe diagnostic paths or repairs requiring secret inspection remain blockers, and no tool or permission bypass is authorized.
- Empty package directories are not tracked; a directory appears in a package only when it holds a managed file.
- A change that alters deployed state, such as the package layout or link targets, is deployed on the host where it is made, and the same commit adds a host pass item to `docs/maintenance.md` with the exact steps for the other host; the agent runs that item in the next session on that host, after H pulls, and removes it when done.
- `make lint check` are the repository checks and `make restow verify` the host checks; the ship skill runs them on the staged state before a commit. Node.js and mise are verification prerequisites. The OpenCode package supplies startup defaults through `~/.config/mise/conf.d/eyragents-opencode.toml`; supported launches use mise activation, shims or `mise exec`. `tests/mise-env.sh` checks this without host configuration. `make canary` is separate behavioral smoke: up to six calls per tool, successful nonempty replies required, with fixture HEAD preservation. Failure exits 1, skipped/unverified checks 2, and success 0 is not independent dispatch proof. Restart OpenCode after config/skill changes. Keep genuinely pending host evidence and revalidation triggers in the ledger.

## Skills

- `ship`: commit verified work and publish it; all cards of a round first, then H approves each commit and push at the native prompt.
- `spar`: independent review from concepts to details, by the in-tool auditor or the other tool's model.
- `eyrsync`: this repository's own skill, under `.agents/skills` with a `.claude/skills` directory link, since Claude Code reads only `.claude/skills` and OpenCode discovers `.agents/skills` natively. Check reference/evidence coverage for every tool, then reconcile official docs/releases, role-appropriate source/public material, runtime evidence and the Agent Skills specification; maintain this repository's reference lifecycle and the workspace guide's AI-client reference.
- `omarchy`: required for end-user Linux desktop, Hyprland, Omarchy, terminal, theme, and display configuration. Omarchy installs it and `diagnose-crash` as links under `~/.claude/skills` and `~/.agents/skills`; they resolve outside the packages, and `make clean` never touches them.
