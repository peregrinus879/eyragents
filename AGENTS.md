# AGENTS.md - EyrAgents

EyrAgents is a standalone GNU Stow repository for shared Claude Code, Codex, OpenCode, and Hermes Agent configuration. It has no host-dotfiles repository dependency. Keep changes portable across the supported Omarchy and Arch WSL environments unless a platform-specific scope is explicit.

## Loading and Ownership

- Claude Code loads `~/.claude/CLAUDE.md`, its documented user instruction file and a tracked symlink to shared guidance, then this file through the root `CLAUDE.md` import. Codex loads `~/.codex/AGENTS.md`, a tracked symlink to shared guidance, and this file. OpenCode loads shared guidance through its native global `~/.config/opencode/AGENTS.md` symlink and this file; no explicit `instructions` duplicate is configured, and project `CLAUDE.md` fallback remains enabled.
- `agents/.agents/shared-guidance.md` is the canonical cross-tool policy and `agents/.agents/skills/*/SKILL.md` are the canonical skills, in the tool-neutral package that deploys `~/.agents`, the Agent Skills standard's home, which Codex reads natively. Claude Code, Codex and OpenCode use tracked global-instruction symlinks; Hermes composes that neutral source into its stable environment hint. Claude Code's `~/.claude/skills/<name>` entries hold tracked symlinks to each skill's `SKILL.md` and scripts; OpenCode's `skills.paths` names the deployed skills directly. The skills' executables live where the Agent Skills specification puts them, `skills/<name>/scripts/`: `commit-candidate`, `commit-apply`, and the shared `governance.py` implementation under `commit`, `publish-bind`, `publish-apply`, `publish-verify`, and `publish-clip` under `publish`, `review-brief`, the bridges, and the scanner under `spar`; `make stow` installs `templates/hooks/commit-gate` as a real file. The skills call the scripts, so the procedure is code and the prose is intent. Order tools as Claude Code, Codex, OpenCode, Hermes Agent.
- This file owns repository invariants. `README.md` is the public overview and navigation entry point; `docs/setup.md` owns installation/deployment and `docs/operations.md` owns usage/verification. `docs/design.md` owns architecture and rationale. `docs/access.md` owns the cross-tool access comparison, restricted launches, implementation references, and official-source baseline; read it first for access questions and reconcile it through `/eyrsync`. Skills own workflow procedure and script headers own local constraints. `docs/maintenance.md` holds unresolved decisions, deferred work, active limitations, and dated revalidation evidence. Update each fact at its owner and link to it; keep README detail proportional. Git history owns provenance.
- `docs/agent-guide.html` and `docs/agent-guide-src/` own the offline AI-client reference. AI-client control, workflow and inherited-default changes include reconciliation here through `/eyrsync`; no host-repository companion is required. Preserve source/runtime evidence distinctions. `make agent-guide` rebuilds the output and `make check` rejects staleness; neither proves live key delivery.
- [Develop's workstream contract](agents/.agents/skills/develop/references/workstream.md) owns the primary's compact checkpoint, working artifacts, `audit/` and `spar/` files and dependency-aware cleanup. Reviewers remain read-only. Full drafts/evidence have one owner and are linked from current state. Receipt close-out is separate and owned by commit; tracked `docs/handoff.md` carries only concrete cross-host work, never approval.
- Root wrappers and documentation are source-only; Stow deploys package contents. Because the packages are live configuration on a stowed host, an edit to a settings file, skill, or bridge here is active for the next session of that tool before any commit; work on this repository only in a session H is watching.

## Security Boundaries

- Authentication, credentials, session state, and generated host state stay out of Git. The tracked Claude settings are the only app-managed rewrite exception; preserve and review those rewrites instead of reverting them.
- Maintain the common finite [protected-path inventory](docs/access.md#protected-paths) across primary controls, reviewer bridges and scanner, with native gaps explicit. It covers credential/auth/key/browser/password-manager stores, environment files, known histories, system secrets, raw dumps/interfaces and recognizable copies, including `*.keytab` and private `ssh_host_*_key`. `tests/safety-paths.json` is a synthetic corpus, not a deployed dependency. Match exact system files and component-boundary trees; keep ordinary configuration, public host keys, `example.env` and `credentials-policy.md` usable. The Codex agent has no read grant on `~/.codex/config.toml`. Finite path checks cannot classify arbitrary renamed secrets or every hardlink/hidden outward alias; search, shell and client-internal coverage differ.
- General-browse exclusions are not blanket OS masks: preserve authorized programs' normal runtime interfaces and task-scoped non-secret diagnostics, while excluding raw payload/interface file-tool targets. Managed mount-aware predicates give unknown affected mounts no new automatic grant. Static grants, native rules and guidance remain distinct; the access matrix owns supported scope and evidence.
- Git internals are protected in layers: native rules deny `.git/**` writes on checked targets; OpenCode adds protected/Git source/destination preflight while retaining its [Move-to permission gap](docs/access.md#move-destinations). Codex configures workspace `.git/config` and `.git/hooks` read-only, subject to its documented sandbox-construction limits. Claude Code's classifier requires explicit instruction for Git configuration changes, with the bounded, pinned-identity Eyrsync reference-updater exception below; OpenCode's named configuration asks remain. Reference authority does not bypass native restrictions or authorize arbitrary config, hook, alias or publication changes.
- Claude Code's and Codex's `PreToolUse` hooks and the OpenCode commit-gate plugin run `commit-gate` before shell commands. It denies commit-producing Git forms, aliases, opaque subcommands, and ambiguous input; `merge`/`pull --ff-only` exemptions require unambiguous literal options and reject conflicting ff, rebase, squash, and bypass options. This is shell-text enforcement, not containment of scripts hiding Git operations. Raw Git commands H wants run are H's own through `!`; prose containing them is written with file tools. The installed gate is a real copy under `~/.agents/hooks`, outside workspaces because Codex hooks execute outside its sandbox; file tools may not edit it. Enabling Codex hooks also loads project-local hooks in trusted projects, so untrusted checkouts use the launches in `docs/access.md#untrusted-checkouts`.
- `commit-candidate` records the prepared index by default; explicit `--stage` stages whole literal intended paths only after mixed-file and path preflight. Immutable SHA-256 receipts bind tree, parent, branch, message, identity and worktree; mutable status and common-Git-directory locks govern cooperating operations. Apply/show/clear/close/publication operations require exact IDs. Normal close-out requires selected eligible publication ancestry; `--accept-unverified` needs H's accepted disposition without a success claim. For an explicitly local-only endpoint, `--local-only` validates actual committed candidate objects and refuses publication records in the selection; the primary checks remaining dependencies. Preview either disposition with `--dry-run`. Preserve active/ambiguous/corrupt/foreign-worktree state. Transient closing markers retain the disposition for resumable deletion. Staging recovery requires a matching prefix containing the complete coverage proof, receipt ID and outcome; empty or shorter staging refuses unchanged even on an identical retry. The [commit skill](agents/.agents/skills/commit/SKILL.md#close-out) owns full recovery preflight; stable lockfiles remain. Records do not attest approval, gates or fresh remote state.
- `commit-apply ID` uses an isolated index and normal hooks, then validates the actual tree, complete parent list, message, author/committer, and branch position. Rejection never restores the original index or worktree. Compensation is conditional: only the uniquely identified commit created by this invocation, still on the recorded branch with its recorded sole parent, may be compare-and-swapped back. Ambiguous evidence, moved checkout/tip, or failed CAS preserves state and stops for H. These are trusted-repository governance checks, not an unconditional branch-advance or same-user isolation guarantee.
- Commit review stays individual: one compact candidate card, one staged diff and one exact approval at a time. Routine pushes use one consolidated summary and one approval for a fixed ordered set of immutable bindings. Short visible references resolve to full recorded IDs; technical hashes/argv/context stay available on request, while material exceptions remain visible. Set approval permits one attempt per listed binding, with separate calls and verification in order. Drift, failure or interruption stops the set; the unattempted remainder needs fresh approval. No commit squashing, blanket authority or all-or-nothing guarantee follows. The commit/publish skills own the card fields and procedure.
- Commit/publication approval also covers necessary failed-CI reruns for those exact published repositories/commits under the publish skill's CI rerun procedure, without another prompt. The primary checks run/job ownership, full SHA, cause and repeated effects, then verifies a bounded retry. OpenCode allows the rerun command family and Claude's classifier recognizes the exception; this is workflow-scoped authorization, not receipt-enforced native matching. Other mutations and Codex's network boundary retain their existing rules. Restart OpenCode after permission changes before claiming live activation.
- `publish-bind` scans new commit metadata, explicit per-parent merge patches, the flat diff, and complete newly reachable text blobs and tree paths. Unscannable objects have digest-bound metadata and require H's inspection, never a fabricated complete scan. Normal executable pre-push hooks are inventoried and content-fingerprinted for review, not skipped; unsupported/sensitive hook targets and configured scope-expanding options/helpers refuse. The immutable binding names the resolved endpoint and exact branch/base/reviewed commit plus configuration. After H's contemporaneous approval of the exact set containing that binding and necessary native execution authority, `publish-apply ID` holds the common-directory lock across recheck and one bounded noninteractive direct-argv push. Technical packet and executor share argv generation: configured remote name for tracking/hooks, immutable reviewed SHA, explicit branch refspec, exact-base lease, normal `--verify`, and tag/submodule/redirect suppression. Only ready records execute; a durable pre-spawn `executing` marker prevents replay after lost results. Handled outcomes become `attempted`, never ready, and may have published despite failure. `publish-verify ID` separately observes the bound endpoint through read-only `ls-remote`, retaining attempted evidence on drift and execution outcomes on verification. It may also run trusted-worktree make/npm targets, so the whole verifier is not intrinsically read-only. Tracking, CI and deployment remain distinct; mismatch does not prove the push never landed. Executing/unconfirmed-cleanup records stay protected, and eligible attempts need explicit accepted-unverified close-out if unverified. Missing first-publication baselines need a separate full-history procedure.
- GitHub publication normally uses HTTPS with the host's standard `gh` credential helper. This repository documents standalone onboarding; H handles login, storage choices and recovery locally. Authentication readiness is not an extra per-push approval gate, and credential access carries account permissions rather than read-only isolation or publication approval. EyrAgents neither inspects credential stores nor configures global authentication. Preserve the bound endpoint, selected transport, TLS validation and SSH host trust where applicable; existing SSH support uses the caller's normal configuration and inherited `SSH_AUTH_SOCK`. Client noninteractive flags and process-group cleanup do not control independent provider dialogs; retain honest timeout/unknown outcomes and no replay. Codex retains command-network and protected-file restrictions; its denied-read policy also prevents native unsandboxed execution. It prepares the review and hands publication to an independently launched network-capable primary, which checks the context and obtains H's fresh exact-binding approval. Never launch a nested client, broker, override or sandbox-first attempt to bypass that boundary. The publish skill owns the handoff; the ledger owns version revalidation.
- Trusted-repository defaults are not an isolation boundary against hostile project configuration. Use the restricted launches in `docs/access.md#untrusted-checkouts` for untrusted checkouts.
- Primary web research follows each tool's managed policy: Claude Code and OpenCode keep web fetch and search, and Codex keeps live web search plus its desktop-app apps, browser, hooks, and plugins. These are egress and authority surfaces for a prompt-injected session, kept by H's choice. Reviewer web tools and command network remain disabled.

## Reviewer Bridges

- Claude Code reviews with Codex through `spar-codex`. Codex reviews with Claude manually outside its strict profile. OpenCode's configured Claude path is `spar-claude`; active availability is recorded in the maintenance ledger. The bridges, `spar-payload-scan`, and `review-brief`, which assembles the artifact both spar and the auditor take, live in the spar skill's `scripts/` under `~/.agents`, shared by every tool like the skill itself.
- Each bridge runs one read-only, offline, subscription-authenticated, single-turn reviewer from the caller's repository root. Unset `spar.consent` permits review; when set, only literal `true` passes, and empty values or lookup failures refuse. Flags are hard-coded: the reviewer reads the repository except Git internals and credential-shaped paths, has no write, web, MCP, plugin, subagent, or project-instruction surface, starts from a scrubbed environment, and runs under a hard timeout in its own process group. The Codex reviewer uses a read-only, network-off sandboxed shell; the Claude reviewer has only Read, Glob, and Grep. Reply-only stdout stays separate from stderr's validated reviewer ID and safe `model`/`effort`/`tier`/`clientversion` provenance. Unexposed or unsafe values are `unknown`, never inferred from configured preferences.
- Review-recommended paths: a staged change to `claude-code/.claude/settings.json`, `templates/codex/config.toml`, `opencode/.config/opencode/opencode.json`, a bridge, the scanner, `templates/hooks/commit-gate`, a skill script under `agents/.agents/skills/*/scripts`, the OpenCode plugin, or `agents/.agents/shared-guidance.md` is where a spar or auditor review before the packet earns its cost. No review is mandatory. Save in-tool audit evidence under the workstream's `audit/` and cross-vendor spar evidence under `spar/`; the primary records and removes those documents under the shared lifecycle, not the review agents.
- `spar-payload-scan` bounds requests/artifacts, rejects credential-shaped values and sensitive paths (including copied stores), inlines artifacts, and rescans replies. Bridges pass `outbound --root REPO [--scratch-root PRIVATE_TMPDIR] -- FILE...`, keeping artifact operands out of options. Temporary artifacts require an explicitly selected private, owned caller `TMPDIR` below `/tmp` or `/var/tmp`, not a shared tool root; lexical and resolved paths are checked. This selects a private directory, not a new trust tier or proof of session identity. Reviewer runtimes may not resolve inside the repository or temp roots; reviewers receive no scratch-write grant. Addition-only `diff` mode is not complete publication coverage: governance also scans complete new objects and raw commit metadata.

## State and Deployment

- Stow runs with `--no-folding`, so managed parents stay real directories and only leaves are links; each `~/.agents/skills/<name>` is the exception, linked whole because Codex follows directory links but skips file links. Every host-writing Make entrypoint requires the deployed-clone guard. `install-gate` accepts only the fixed canonical `~/.agents/hooks/commit-gate` endpoint outside Git workspaces, with real, non-symlinked parents and an owner-controlled, single-link regular file if the endpoint exists; `GATE` cannot relocate it. `check-skills` preflights all selected skills before cleanup/conversion; foreign entries refuse unchanged. Cleanup removes only recognized dangling package links and retired directories left empty. `.NOTPARALLEL` serializes one Make invocation, not independent deployment processes or disk failures.
- `verify-deploy` uses preparation's read-only `--check-gate` mode, sharing installation's fixed-endpoint, parent, ownership and link checks, then requiring executable content equal to the template. A missing or unsafe gate refuses before other deployment verification; verification never installs or repairs it.
- Codex reconciliation installs a host-local file: the template owns root keys and its tables; host-only tables and `hooks.state` survive with their parsed semantics verified before replacement bytes are emitted. Complete TOML prefixes distinguish real sections from multiline values; unsupported inline/dotted trust-state layouts refuse without writing or printing values. Root `service_tier` stays host-owned while the template omits it, unless the host root exactly matches a committed template root; that textual residue rule remains, so an uncommitted-template root retains the key. `make verify` checks the installed template boundaries, not host-secret contents in reports.
- Run authorized host gates through their reviewed entrypoints when native permissions allow: normal reconciliation keeps merged configuration in a private local file and exposes structural checks, not raw values. Do not turn possible secret-bearing host state into a blanket manual handoff, but never open/dump that state or run `merge` against a host file into visible output. Actual access refusals, unsafe diagnostic paths, or repairs requiring secret inspection remain blockers; no tool or permission bypass is authorized.
- Hermes configuration is also potentially credential-bearing. The primary profiles, reviewer bridges and scanner protect `.hermes/config.yaml` alongside existing `.env`/`auth.json` rules. Use only the opaque reconciler for host configuration; authentication is H's interactive `hermes model` step. Python with PyYAML is required for repository and deployment checks. Restart Hermes after deployment, and OpenCode after its permission changes.
- The Hermes canary uses ordinary `--cli chat --source tool --quiet --query`, never top-level `--oneshot`, which bypasses approvals in v0.19. The source tag keeps automation out of ordinary continuation selection. It skips inherited bypass/customization-disable flags or alternate profiles. Interactive approval prompts and asynchronous child completion remain separate acceptance cases. The native model wizard's canonical Codex base URL and an agreeing model alias are preserved by reconciliation; model.default/provider remain template-owned.
- Empty package directories are not tracked; a directory appears in a package only when it holds a managed file.
- A change that alters deployed state, such as the package layout, link targets, or the host Codex config, is deployed on the host where it is made, and the same commit adds a host pass item to `docs/maintenance.md` with the exact steps for the other host; the agent runs that item in the next session on that host, after H pulls, and removes it when done.
- The [verification contract](agents/.agents/skills/develop/references/verification.md) is shared by develop, commit and publish: `make lint/check` are repository checks and `make restow/verify` host checks. Node.js and mise are verification prerequisites. The OpenCode package supplies startup defaults through `~/.config/mise/conf.d/eyragents-opencode.toml`; supported launches use mise activation, shims or `mise exec`. `tests/mise-env.sh` checks this without host configuration. `make canary` is separate behavioral smoke: up to six calls per tool, successful nonempty replies required, with fixture HEAD preservation. OpenCode uses a local README and performs the preapproved `/usr/lib/os-release` read; only its general external-temp read stays interactive-only and skipped. Failure exits 1, skipped/unverified checks 2, and success 0 is not independent dispatch proof. Restart OpenCode after config/skill changes. Keep genuinely pending host evidence and revalidation triggers in the ledger.

## Skills

- `develop`: lead substantive work from its goal to a verified result, maintain lean recovery state, and hand off to commit preparation when appropriate.
- `commit`: run the repository's gates, then stage, review, and commit one exact atomic change with H's approval.
- `publish`: review every listed binding, obtain H's approval of the fixed publication set, then execute and verify each exact ID separately in order.
- `spar`: value-based cross-model review through a read-only reviewer bridge.
- `eyrsync`: this repository's own skill, under `.agents/skills` with a `.claude/skills` symlink, since Codex and OpenCode discover `.agents/skills` natively. Check reference/evidence coverage for every tool, then reconcile official docs/releases, role-appropriate source/public material, runtime evidence and the Agent Skills specification; maintain this repository's reference lifecycle and standalone AI guide.
- `omarchy`: required for end-user Linux desktop, Hyprland, Omarchy, terminal, theme, and display configuration. Omarchy installs it and `diagnose-crash` as links under `~/.claude/skills` and `~/.agents/skills`; they resolve outside the packages, and `make clean` never touches them.
