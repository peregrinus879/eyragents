# Review Methods

Select checks that bear on the acceptance conditions; this is a menu, not a compulsory sequence. Use available tools freely within the review boundary. A check that could not run remains unverified.

| Work | Evidence to examine |
| --- | --- |
| Decisions and plans | Intended outcome, genuine constraints versus suggested methods, strongest alternative, likely future costs, dependencies and reversibility. Reopen an informed choice only when its basis changes. |
| Software | Observed behavior, interfaces and consumers, failure paths, tests and the environment in which they ran. Inspect relevant surrounding code, not only changed lines. |
| Factual claims | Governing source revision and exact supporting passage, page, clause or record. Verify attribution against the original rather than an inherited summary. |
| Calculations and forecasts | Input population and completeness, units, dates, currency and basis, assumptions, method and reproducibility. Independently check material results; the same authoritative inputs may be appropriate. A quote is not proof of a calculation or inference. |
| Document packages | Missing or duplicate records, references and inconsistent values or scope. Compare both directions of set differences; matching totals can hide offsetting errors. Agreement between documents does not establish correctness. |
| Final artifacts | The actual delivered revision: tables, figures, formulas and rendered output where tools permit. Generator success and matching hashes do not establish a valid or usable artifact. |

For every material finding, identify the evidence and what would resolve it. Treat a proposed correction as another claim to verify. Separate extraction, calculation and inference; state consequential uncertainty. Governing status and revision take precedence over modification time. H's acceptance of advice is distinct from a client's authority to change its baseline, records or commitments.
